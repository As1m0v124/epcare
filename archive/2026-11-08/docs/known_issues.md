# 问题台账（Known Issues）

> 记录项目以来遇到的所有问题、根因与处理，持续更新。按出现顺序编号。

## 环境 / SDK

| # | 问题 | 根因 | 处理 | 状态 |
|---|---|---|---|---|
| 1 | `uv pip install robomaster` 无 macOS wheel | 官方只发 manylinux/win wheel | 拆 manylinux wheel 装纯 Python 部分 + 3 补丁（`scripts/install_robomaster_mac.sh`） | ✅ 已解 |
| 2 | SDK `initialize()` 崩溃 | 相机模块初始化急切创建视频解码器（macOS 无 libmedia_codec） | 解码器按需创建 + 流启动保护 | ✅ 已解 |
| 3 | 命令行传参连不上（`conn_type='sta'`） | SDK 用 `is` 比较连接类型，非驻留字符串身份不等 | `conn.py` 三处 `is` → `==` | ✅ 已解 |
| 4 | macOS 无视频流 | 解码器仅 Linux/Windows 二进制 | **TCP 40921 直连裸 H.264 + PyAV 解码**（含逐块解码、看门狗、重连） | ✅ 已解 |
| 5 | 机械臂位置出现 42 亿异常值 | SDK 用无符号 `<II` 解码位置，y 负值溢出 | 改为有符号 `<ii`（补丁入安装脚本） | ✅ 已解 |
| 6 | `servo.drive_speed` 锁死机械臂 | 舵机速度模式与机械臂高层控制互斥 | 禁用；线性动作改用闭环步进 | ✅ 规避 |
| 7 | 机械臂下降/小步不动 | 单步 <8–10mm 被静默忽略（动作仍返回成功） | 步长统一 ≥10mm | ✅ 已解 |
| 8 | 机械臂「到限位」误报 | 1 秒无位移判定过急；限位随姿态耦合 | 3 秒窗口 + 连续两次失败才提示 | ✅ 已解 |
| 9 | 低电量时机械臂指令成功但不动 | ≤40% 电量功率保护 | 记录规律；充至 >80% 恢复；服务设 25% 拒动 | ✅ 已知 |
| 10 | 跨网段找不到机器人 | Mac 与机器人不同网段，SDK 扫描选错网卡 | `EP_IP` 固定 IP 直连（`config.ROBOT_IP_STR`） | ✅ 已解 |
| 11 | 整机掉线（ping/广播皆失败） | 机器人 Wi-Fi/系统挂起 | 关机重启；服务加自动重连（12 次×5s） | ✅ 已解 |

## 验收专项（2026-11-10）

| # | 问题 | 根因 | 处理 | 状态 |
|---|---|---|---|---|
| 24 | 操控次数多后指令堆积卡死 | `/move`、`/arm`、`/grab` 在 FastAPI 线程池里各自并发调 SDK；SDK 动作通道一次只执行一个动作，请求无限排队；状态接口走缓存所以页面“看着正常”。并发数一多，后续指令要等数十秒甚至超时，只能重启服务（与 #14/#16 同源） | **有界动作队列 + 单工作线程**：全部动作进入 `Queue(maxsize=2)`，1 条执行 + 1 条排队，其余立即 429；执行超时 504；急停清空队列；队列模式强制等待动作完成（避免撞 SDK already performing）。`EPCARE_LEGACY=1` 可切回旧行为复现 | ✅ 已解（真机 36 并发前后对比，见下） |

**真机对比（同一脚本 `scripts/repro_pileup.py --n 36`，机器人已连接 real、电量 95%）**

| 版本 | 批量结果 | 请求延迟 p50 / max | 堆积期间 `/state` | 堆积期间新指令 | 判定 |
|---|---|---|---|---|---|
| 旧版（legacy 直接并发） | 两次：22×200+14 超时 / 33×200+3 超时 | 18.3/20.0s；12.5/20.0s | 0.001s（缓存正常） | **10.0s 超时** | ❌ 卡死复现 |
| 修复版（有界队列） | 3×200 + 33×429 | 0.01s / 1.22s | 0.003s | **0.40s 返回 200** | ✅ 不再卡死 |

证据：`results/pileup_before.json`、`results/pileup_webdemo.json`、`results/pileup_after.json`、`results/web_freeze_annotated.png`（整页截图）、`results/pileup_before_annotated.jpg`、`logs/control_audit.jsonl`（含 `queue_full` 记录）。p50 随队列残余动作浮动，稳定判据是探测指令超时。

**舵机连续步进（真机 20 步 ±10mm，工作区中部，逐步回读）**

| 指标 | 结果 |
|---|---|
| 执行成功 | 20/20（HTTP 200） |
| 单步到位误差 | 平均 1.55mm，最大 2mm，20/20 ≤3mm |
| 方向正确 | 20/20（正/负指令方向一致） |
| 20 步净漂移 | x +3mm（命令正负交替，理论 0） |

证据：`results/servo_stability.json`。说明：机械臂位置控制仍是“发步进+等完成”的开环步进，单步误差 ≤2mm；之前“按多了卡死/丢步”主要来自并发排队（#14/#24），队列化后不再出现。

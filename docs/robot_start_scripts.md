# 两个机器人连接脚本（旧版卡死演示 / 修复版正常控制）

桌面已放两个双击入口：

| 入口 | 作用 |
|---|---|
| `EP旧版_卡死演示.command` | `EPCARE_LEGACY=1` 启动旧行为 → 自动连机器人 → 打开网页 → 按回车跑 36 条并发 → 生成“卡死”标注图 |
| `EP修复版_正常控制.command` | 默认有界队列启动 → 自动连机器人 → 打开网页 → 自由控制，不卡死 |

## 旧版：复现卡死并标注

```bash
bash scripts/start_legacy_freeze_demo.sh --run-demo
# 用移动小车演示（默认机械臂）:
DEMO_ACT=move bash scripts/start_legacy_freeze_demo.sh --run-demo
```

流程：
1. 旧行为启动（`EPCARE_LEGACY=1`，直接并发调 SDK，无队列）；
2. 自动等待机器人上线并连接（最多 120 秒）；
3. 打开网页客户端；
4. 按回车后并发发 36 条动作，再发第 37 条探测；
5. 生成 `results/pileup_before_annotated.jpg`：动作类型、批量结果、探测耗时、画面变化百分比、判定；
6. 终端同时打印 JSON 判定（`frozen: true`）。

注意：旧版跑完队列里还有动作，只能重启控制服务；这就是“以前卡死要重启”的演示。
机械臂动作需要周围清空；用 `DEMO_ACT=move` 是原地转，不需要大空间。

## 修复版：自动连接 + 自由控制

```bash
bash scripts/start_fixed.sh
```

流程：
1. 启控制服务（有界队列，1 执行 + 1 排队）+ 后端；
2. 自动等机器人上线并连接；
3. 打开 `http://127.0.0.1:8000`；
4. 登录 `admin / admin123`，驾驶舱/巡检页可自由控制。

连续快速点击可能看到 429「机器人正忙」——这是主动限流，等 1 秒再按，不是卡死。

## 前提
- 机器人已开机、与 Mac 同一 Wi-Fi；IP 默认 `10.197.63.238`，不同时用 `EP_IP=...` 覆盖；
- 两个脚本都会先停掉占用 8000/8001 的旧实例，不要同时跑两个；
- 电量 >25%（真机动作门槛），建议 >50%。
